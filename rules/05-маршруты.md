# Маршруты задач 1С

## Сначала определить источник

Осмотри корень нужного проекта. Запиши формат, авторитетный экземпляр и версию.

| Формат | Признаки | Путь работы |
|---|---|---|
| Выгрузка Конфигуратора | Configuration.xml и XML объектов | Инструменты XML/CLI, схема целевой платформы, проверка загрузкой на копии |
| EDT | .project с nature V8ConfigurationNature или V8ExtensionNature, файлы MDO | Семантические сведения EDT, операции через владельца модели, валидация проекта |
| Гибрид | Несколько представлений одной конфигурации | Сначала определить первоисточник и команду конвертации, затем менять одно представление |
| Формат не установлен | Недостаточно признаков или противоречия | Уточнить устройство проекта до правок метаданных |

При EDT сначала используй доступную семантику для поиска вызовов, ссылок,
модулей и метаданных. Если её нет, явно зафиксируй ограничение и согласуй
безопасный маршрут. Рецепт XML Конфигуратора к MDO не применяй. Согласуй владельца
изменений между моделью EDT и диском, затем проверь синхронизацию.

## Подобрать возможности по задаче

| Задача | Что установить до правки | Чем подтвердить результат |
|---|---|---|
| Метод BSL | Вызовы, публичный контракт, API целевой платформы и БСП проекта | Синтаксис, применимый анализ и затронутый сценарий |
| Метаданные | Полный путь объекта и реквизита, тип, версия конфигурации | Валидатор проекта, загрузка на копии и использование объекта |
| Форма | Вид формы, реквизиты, команды, события | Открытие и действия в разрешённом тестовом клиенте |
| Запрос | Схема источников, типы, параметры и объём данных | Исполнение, ожидаемая выборка, замер при заявлении об ускорении |
| Дефект | Воспроизведение, ожидаемый результат, конкурирующие гипотезы | Красная и зелёная пробы на уровне дефекта |
| Права, движения, транзакции | Сценарии доступа, границы записи и риск | Полная проверка по правилу 04.2 с положительными и отрицательными случаями |

Справочник не подменяет API конкретной версии. Авторские отметки, стиль,
изменение заимствованного кода и правила БСП бери из текущего проекта.
Рекомендации стандартов проверяй с условиями применения, включая объём данных.

## Проверить доступность инструмента

Для каждой нужной возможности различай три состояния.

1. **Настроена** — есть конфигурация подключения и версия провайдера.
2. **Видна клиенту** — операция доступна текущему агенту.
3. **Проверена на проекте** — безопасная контрольная проба дала ожидаемый эффект.

Зафиксируй полноту индекса и область проверки. Неподключённый обязательный
инструмент оставляет соответствующий уровень непроверенным. Паспорт проекта
хранит эти сведения без секретов. Названия MCP-операций определяются провайдером.
