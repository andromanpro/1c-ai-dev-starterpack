# Стандарты разработки 1С: Управляемые формы (оформление и компоновка)

> **Подключаемый справочник** набора практик: в обязательное ядро не входит.
> Агент читает его по указанию человека или при работе с задачами этого класса.

> Источник: официальные стандарты разработки интерфейсов 1С (v8std/ИТС —
> 702, 717, 722, 753 и связанные) в собственном конспективном изложении,
> плюс практика автора. Открытые компиляции на эту же тему перечислены
> в `docs/справочник-инструментов.md`.
> Применимость: 1С:Предприятие 8.3, управляемое приложение.
>
> **Это про то, как форма выглядит и ведёт себя.** Код формы — директивы компиляции,
> асинхронность, переходы клиент-сервер — в `код.md` §4. Обычные формы
> (8.1/8.2, legacy) — в `обычные-формы.md`, туда не заглядывать при работе с УФ.

## 1. Выбор элемента под задачу

Самая частая ошибка — взять флажок там, где нужен переключатель. Таблица решает
90 % случаев:

| Ситуация | Элемент |
|---|---|
| Два состояния, оба очевидны из заголовка | Флажок |
| Два состояния, действие применяется сразу и влияет на форму заметно | Выключатель (тогл) |
| Один вариант из 2–5, варианты требуют пояснения | Переключатель |
| Один вариант из 3–5, короткие подписи, форма под ним перестраивается | Тумблер |
| Один вариант из 6 и более | Поле ввода со списком |
| Переход к другой форме | Гиперссылка |
| Действие над данными, необратимая операция, выбор/подбор | Кнопка |

Уточнения:

- Флажок — заголовок **справа** (отойти от умолчания платформы).
- В заголовке флажка **никаких отрицаний**: «Не проводить при записи» выключенным
  читается как двойное отрицание.
- Выключателей на странице — не больше 2–3.
- У переключателя значение по умолчанию идёт **первым**. Переключатель действует на
  то, что справа и под ним.
- Тумблер для двух значений не использовать — непонятно, какой пункт выбран.
- Повторяющиеся слова из вариантов переключателя/тумблера выносить в заголовок.

## 2. Поля ввода

1. Ширина — под самое длинное ожидаемое значение, не «на всякий случай».
   Ссылочные поля: `МаксимальнаяШирина = 27`.
2. Кнопка очистки (×) — если пустое значение допустимо. Исключение: отборы на формах,
   там флажок.
3. Подсказка ввода для пустого значения обязательна, если пустое значение осмысленно
   («По всем организациям»).
4. Строка длиннее 100 символов — многострочное поле, заголовок **сверху**.
   Комментарий: Ширина 79, Высота 3, растягивание отключено.
5. Часто повторяющиеся значения (период, организация, склад) — сохранять последний
   выбор пользователя.
6. Заголовок можно скрыть ради места, но тогда подсказка ввода обязательна.
7. Составной тип — **не** платформенный выбор типа, а отдельное поле выбора типа.
8. Поле выбора с единственным значением не делать: заполнить реквизит кодом, поле
   скрыть функциональной опцией.

## 3. Кнопки, команды, гиперссылки

1. Заголовок кнопки описывает действие. Не экономить на длине ради краткости.
2. Основная команда: слева вверху для полноэкранных форм («Провести и закрыть»),
   справа внизу для небольших/модальных («ОК»).
3. Кнопка по умолчанию на форме **одна**. При переключении страниц — переназначать.
4. Кнопка не ведёт на другую форму, гиперссылка не меняет данные. Если кнопка всё же
   открывает форму — сказать об этом в заголовке («Показать настройки»).
5. Гиперссылка: осмысленный и достаточно длинный текст, из него понятно, куда ведёт.
   Слова «здесь», «тут», «подробнее» — нет. Две ссылки подряд — нет. Цвет не менять.
6. Команда, работающая со строкой списка, называется по действию над строкой.
7. У команды, меняющей данные, взвести **«Изменяет сохраняемые данные»** — иначе не
   поднимается `Модифицированность`, и при `ТолькоПросмотр` кнопка останется активной.

## 4. Табличные части

1. Заголовок — в одну строку. Сложные пояснения уходят в подсказки внутри таблицы.
2. Одна колонка — заголовок таблицы убрать, назначение описать декорацией.
3. Служебная пустая колонка справа для управления шириной: без заголовка,
   «Только просмотр», «Растягивать по горизонтали».
4. Заголовок колонки прижимается туда же, куда значение: число — вправо, строка и
   ссылка — влево (по умолчанию).
5. У страницы с табличной частью заполнять **`ПутьКДаннымЗаголовка`**
   (`Объект.Товары.КоличествоСтрок`) — счётчик в заголовке страницы.
6. Реквизиты шапки и табличные части — на разные вкладки («Основное», «Товары»).

## 5. Группы и компоновка

1. Заголовок группы — только если он что-то добавляет; слово «Группа», которое
   подставляет платформа, из интерфейса убрать. Платформенные подсказки групп — тоже.
2. `Расположение = Горизонтально` избегать: расчёт от минимального 1280×768.
3. Свертываемая группа — снять «Отображать отступ слева», заголовок описывает
   содержимое («Банковский счёт и адрес»). Не размещать выше обычных групп.
4. Во всплывающей группе — `Отображение управления = Картинка`, говорящий заголовок.
5. **Ни в свертываемую, ни во всплывающую группу не прятать обязательные и часто
   используемые реквизиты.**
6. Шапка: сверху вниз и слева направо по важности. Редко меняемые поля (организация,
   подразделение) — правее. Симметрия левой и правой части не самоцель.
7. Поле, меняющее состав формы (вид операции), — **самым первым**. Нижние поля не
   должны влиять на верхние: контрагент выше договора, а не наоборот.
8. Подвал — наименее важное и итоги; по традиции типовых последними идут «Комментарий»
   и «Ответственный».
9. Командная панель: `Источник команд = Форма` для команд объекта, «Глобальные команды»
   для структуры подчинённости и истории изменений. Дублируя стандартную команду,
   отключить её в исходном месте осознанно.

## 6. Диалоги, подсказки, условное оформление

1. Диалог — только для того, что требует явного решения (необратимое действие).
   Текст объясняет последствия и содержит однозначный вопрос.
2. Кнопка подтверждения повторяет действие: «Удалить строки», а не «Да».
3. Закрытие по крестику обрабатывать как отмену — одну из команд диалога задать
   `КодВозвратаДиалога.Отмена`.
4. Подсказка — дополнение к понятному заголовку, заменой ему она не работает. Разовые пояснения —
   через кнопку подсказки; пояснение ко всей форме — сверху; к сложному реквизиту —
   снизу.
5. Условное оформление: одинаковые состояния оформляются одинаково во всём контуре;
   палитру не разводить. **Не использовать условное оформление для управления
   видимостью строк** — это делает отбор или запрос.

## 7. Обязательное по платформе

1. Проверку заполнения делать свойством **«Проверка заполнения»**, а в коде —
   `Если Не ПроверитьЗаполнение() Тогда Возврат; КонецЕсли;`.
   Программная запись обработчик проверки НЕ вызывает (std/463 п.1.3) — для
   программного маршрута нужен свой контроль.
2. В динамическом списке объекта — реквизит `Ссылка` с признаком «Использовать
   всегда» (std/702).
3. На форме списка — `ГруппаПользовательскихНастроек` для показа установленных отборов.
4. Картинки только из библиотеки картинок конфигурации, не из файла.

## 8. Управление видимостью и доступностью

1. Вся видимость/доступность — в **одной** процедуре
   (`ОбновитьВидимостьДоступностьЭлементовФормы`), а не присваиваниями по всему модулю.
2. В выражениях — булева алгебра вместо лестниц `Если…Иначе`.
3. Вызов — **последним** действием, после инициализации и заполнения данных.

## Что сознательно не берём

- **Префиксные служебные группы** (`прфГруппаСпециальная`, `рздСтраницаСпециальная`)
  и «все доработки типовых форм только программно» — это правила доработки чужой
  типовой конфигурации. Для собственных форм они добавляют ритуал без выгоды;
  дорабатываете типовую — берите их из стандартов вендора.
- **Привязка к БПР/УправлениеФормойУХ** — механизмы конкретных вендорских конфигураций.
- **Жёсткие пиксельные размеры кнопок** из мира обычных форм — в УФ размер считает
  платформа.
