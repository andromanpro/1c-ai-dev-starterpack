## Уровни строгости

Каждое правило помечено уровнем. Проверяющему важно различать уровни, чтобы не утонуть в ложных срабатываниях:

- **[HARD]** — автоматический отказ **всегда**, без контекстных исключений. Data loss, security breach, нарушение контракта.
- **[STRICT]** — автоматический отказ для **нового кода**, в legacy/БСП-коде допустимо (но фиксировать как тех.долг). Универсально-правильно, но обоснованные исключения существуют.
- **[SOFT]** — warning, **не блокер**. Стиль, читаемость, перформанс-микрооптимизации. Помечать в ревью, но не валить PR.

Применение в задании агенту:
- При генерации **нового кода** — соблюдать HARD + STRICT.
- При **рефакторинге legacy** — соблюдать HARD, STRICT приоритизировать по контексту.
- При **аудите** — флагать всё, но решение по STRICT/SOFT принимает архитектор/человек.

## Производительность

1. **[STRICT]** Запрос в цикле — `Цикл ... Запрос.Выполнить() ... КонецЦикла`. Использовать пакетный запрос с массивом + `В (&Массив)`. *Исключение*: обработчик очереди по 1 элементу (явно зафиксировать в комментарии). (`код.md`)
2. **[STRICT]** Реквизит через точку — `Контрагент.ИНН`. Использовать `ОбщегоНазначения.ЗначениеРеквизитаОбъекта/Объектов`. (`код.md`)
3. **[SOFT]** Несколько обращений `&НаСервере` подряд в обработчике формы — объединить в один. (`код.md`)
4. **[SOFT]** `&НаСервере` без необходимости в контексте формы — использовать `&НаСервереБезКонтекста`. (`код.md`)
5. **[STRICT]** Виртуальных таблиц в одном запросе > 2 — переписать на временные таблицы, разделить запрос.
6. **[STRICT]** JOIN'ов в одном запросе > 5 — переписать через временные таблицы; запрос на 5+ JOIN-ов отправлять на второе мнение (риск декартова произведения).
7. **[HARD]** JOIN без условия связи — декартово произведение = неверный результат. Каждый JOIN обязан иметь `ПО`-условие.

## Стиль

21. **[SOFT]** Венгерская нотация — `МассивКонтрагентов`, `СоотСоответствие`, `ТЗДанные`. Использовать `Контрагенты`, `ПраваПоРолям`, `ТаблицаДанных`. (`код.md`)
22. **[SOFT]** Тернарный оператор — `?(Условие, Х, Y)`. Использовать `Если ... Иначе`. (`код.md`)
23. **[STRICT]** Имена-резервы из глобального контекста — `Документы = ...`, `Справочники = ...`, `Метаданные = ...`, `Пользователи = ...`, `Константы = ...` — создают ошибки через затенение имён. **Плюс ключевые слова языка как имена переменных**: `Новый = Справочники.Качество.Новый` (Новый — оператор), `Знач = ...` («Ожидается имя переменной»), `Попытка = НоваяПопытка(...)` (Попытка — оператор блока! компилятор молчит до рантайма, EDT EMF-статика 0/0) — не компилируются или мутят парсер; для значений качества/статусов/попыток брать `КачествоНовый`, `СтатусЗнач`, `НоваяПопытка`/`ПопыткаПересчета`. **И в ЯЗЫКЕ ЗАПРОСОВ то же**: псевдоним `1 КАК Есть` падает рантаймом («Ожидается имя», ЕСТЬ — ключевое слово ЕСТЬ NULL); валидатор запроса ловит только если запрос через него прогнали. (`код.md`; реальные эпизоды — четыре кейса за сутки в одном проекте: Новый/Знач в тестах и снипетах, Попытка-переменная и Есть-псевдоним в серверном модуле пересчёта)
24. **[SOFT]** Параметров в процедуре > 7 или необязательных > 3. (`код.md`)
25. **[SOFT]** Глубина вложенности > 4 уровней — использовать ранний возврат (guard clauses). (`код.md`)
26. **[SOFT]** Длина строки > 120 символов. (`код.md`)
27. **[SOFT]** Сравнение булевых с `Истина` / `Ложь` — `Если ЕстьОшибки = Истина` → `Если ЕстьОшибки`. (`обычные-формы.md`)
28. **[SOFT]** `Символ(10)` вместо `Символы.ПС` или другие литералы вместо системных констант. (`обычные-формы.md`)
29. **[STRICT]** Переменная переиспользуется со значениями разных типов — одна переменная = одно назначение. (`обычные-формы.md`)
30. **[STRICT]** `Структура.Свойство("ключ", X)` без объявления `X` ДО вызова — out-параметр должен быть явно объявлен. (из практики)

### Семантика и контракты — кросс-функциональные (2026-07)

> Классы дефектов, проходящие сквозь построчный линт: SonarQube и BSL LS их структурно **не видят** (они не в синтаксисе, а в стыках функций и семантике отказов). Ловятся только семантической проверкой — агент-проверяющий с этим чек-листом читает на контракты и семантику отказов, а не построчно. Выведено из независимого аудита реальных обработок двумя моделями (сверки, штрихкоды, загрузки).

62. **[HARD]** Техническая пустота ≠ бизнес-ноль. Пустой результат от сбоя (HTTP-ошибка, пустой параметр фильтра, не найденный ключ) не должен неотличимо сливаться с легитимным «нет данных». Функция обязана различать «ноль по данным» и «не смог получить» (исключение/статус, не тихий возврат пустого).
63. **[HARD]** Контракт выходной схемы. Альтернативные ветви одной функции (файл/API, тип1/тип2) обязаны возвращать идентичный набор колонок ТЗ; вызывающий читает только гарантированные колонки. Расхождение схем между ветвями = падение вызывающего.
64. **[HARD]** Не найденный ключ → пустая ссылка, трактуемая запросом как «нет фильтра» (`&Ключ = ПустаяСсылка ИЛИ ...`) = выборка по всему множеству под именем выбранного. Останавливать/сигналить явно, не продолжать по «всему».
65. **[STRICT]** JOIN по неуникальному ключу (наименование, артикул без 1:1, обрезанный `ВЫРАЗИТЬ(... КАК СТРОКА(N))` комментарий) без контроля кардинальности → размножение строк и задвоение агрегатов. Соединение должно давать 0/1; множественность — отдельная диагностика, не молчаливое `СУММА`.
66. **[STRICT]** Идентификатор (штрихкод, артикул, код, GUID) через `Формат(...,"ЧГ=0")`/числовой тип — потеря ведущих нулей и точности. Идентификаторы — только строки. Нормализация ключа к числу допустима лишь симметрично для обеих сравниваемых сторон и с явным допущением, что товары не различаются ведущими нулями.
67. **[STRICT]** Достижимая из UI команда, вызывающая функцию-заглушку (пустой текст запроса, `Возврат ""`, TODO) — реализовать либо скрыть/заблокировать команду.
68. **[STRICT]** Внешний вызов (HTTP/веб-сервис): код-состояние вне успешного диапазона → ошибка с журналом; исключение не сворачивается в «Неопределено = нет данных». Явный таймаут обязателен. Расширяет #56.
69. **[STRICT]** Расширяет #30: чтение переменной, которой присвоено значение не во всех ветвях (не только out-параметры структуры) — инициализировать значением по умолчанию до ветвлений.

## Молчаливые отказы платформы

> Платформа не выдаёт ни ошибки, ни предупреждения — последствия всплывают позже и в другом месте. Для агента особенно опасно: нет сообщения об ошибке = «всё получилось».

70. **[HARD]** Снятие объекта типовой конфигурации с поддержки (замка) ради правки — доработка выполняется расширением; снятие с замка — отдельное решение человека, цена: ручное объединение при каждом обновлении. (`код.md`)
71. **[HARD]** Дубли или ручная генерация `uuid` в выгрузке XML — клонирование объекта «по образцу» с чужим uuid, слияние выгрузок без контроля. После массовой генерации/слияния — контроль уникальности uuid + пробная загрузка в пустую базу. (`код.md`)
72. **[HARD]** Строка имени роли в реквизите «Роль» профиля групп доступа БСП — реквизит ссылочный (ИдентификаторыОбъектовМетаданных), строка молча даёт пустую ссылку, роли теряются. Использовать `ОбщегоНазначения.ИдентификаторОбъектаМетаданных("Роль.ИмяРоли")`; общий случай — несовместимый тип присваивается реквизиту молча, проверяй записанное. (`код.md`)

## Тесты на общей информационной базе

> Тесты редко получают базу в единоличное владение: параллельные прогоны, соседние
> наборы и живые данные делят одну ИБ. Убирать за собой «по площади» — значит удалять
> чужое.

73. **[HARD]** Удаление в тестах того, что тест не создавал. Правило владения: **удаляй только то, что создал сам**; общие и заранее существующие данные трогай только внутри транзакции с гарантированным откатом. Цена нарушения замерена на живом контуре: два регламентных задания остались с мёртвыми ссылками, 174 записи-сироты в регистрах, узел плана обмена с меняющейся от прогона к прогону ссылкой. Симптом коварен: свой прогон зелёный, ломается соседний или следующий. (`код.md`)

## Сопровождение

Список — это **выжимка**. Полные объяснения — в `код.md` и `обычные-формы.md`. Если добавляешь новый антипаттерн:
1. Сначала добавь в `код.md` с объяснением **почему**.
2. Потом сюда — одна строка с уровнем + ссылка на пункт исходного файла.
3. Определи уровень: HARD (data loss/security/contract) / STRICT (universally good but legacy may have it) / SOFT (style).

Не дублируй объяснения здесь. Сюда — только rule + reference.
