# Контекст живёт в файлах (ядро)

1. Знание о работе хранится в файлах проекта — стартер сессии, реестры, правила, —
   а не в памяти диалога. Пересказ по памяти проигрывает ссылке на файл.
2. В начале сессии прочитай указанный стартер и источники значимых утверждений.
   Свидетельство проверки связывай с ревизией, версией инструмента, целью и входами.
   При изменении этих оснований перепроверь затронутое. Новая сессия сама по себе
   не обнуляет сохранённый воспроизводимый результат. Надпись «готово» без
   свидетельства остаётся неподтверждённой.
3. Конец значимой сессии: обнови или создай стартер. Фактовую часть **сгенерируй**
   (`tools/handoff-facts.py <репо> --last 15`), руками факты не пиши. Рассказ —
   поверх фактов.
4. Не переноси факты одного проекта в другой. Имя, число, вывод о проекте — только
   из источников **этого** проекта; иначе помечай «гипотеза, требует проверки».
5. Длинный результат клади в файл; в диалог — путь и краткий итог.
6. Правила меняй по поручению человека. Без поручения запиши эпизод трения
   в журнал (`docs/эволюция-правил.md`) и предложи изменение.
