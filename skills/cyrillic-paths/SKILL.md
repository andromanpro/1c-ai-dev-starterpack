# Кириллица в путях на Windows — грабли и решения

Правила, которые повторяются в каждом 1С-проекте: русские каталоги, русские
имена баз и пользователей. Читать до того, как агент первый раз тронет путь
с не-ASCII — иначе сессия застрянет на переборе вариантов.

## Диагностика: что и почему ломается

| Инструмент | Симптом | Причина |
|---|---|---|
| Git Bash (`ls`, `cat`, `rm`, `mv`) | «No such file» на существующем пути | Bash на Windows передаёт аргументы в системной кодировке, NTFS ждёт другую |
| `.ps1` с кириллицей в строках, без BOM | `1С` превращается в `1РЎ` | Windows PowerShell 5.1 читает файл без BOM как ANSI |
| Python, вызванный из Bash с кириллицей в аргументе | FileNotFoundError на валидном пути | Двойная перекодировка по дороге |
| Чтение файла инструментом агента | «Файл не существует» для реального файла | Сбой на смешанной кодировке пути |
| Запуск `1cv8.exe /N "Администратор"` из PowerShell/Python | «Пользователь ИБ не идентифицирован», выход за 1–2 сек | Граница Win32: 1С читает аргументы через ANSI, управляемая среда передаёт UTF-16 — кириллица теряется |

## Правила

1. **Выбор инструмента.** Операции над путями с не-ASCII — через PowerShell
   (корректно работает с Unicode) или файловые инструменты агента. Bash —
   последнее средство; кириллицу как аргумент команды Bash не передавать никогда.

2. **`.ps1` с кириллицей в строках — обязателен UTF-8 BOM.** Файловые
   инструменты обычно создают файл без BOM — после создания добавить:

   ```powershell
   $f = "C:\путь\script.ps1"
   $c = [System.IO.File]::ReadAllText($f, [System.Text.UTF8Encoding]::new($false))
   [System.IO.File]::WriteAllText($f, $c, [System.Text.UTF8Encoding]::new($true))
   ```

3. **Python и кириллический путь** — путь не в аргумент командной строки,
   а внутрь .py-файла (файл в UTF-8), и первой строкой скрипта:
   `sys.stdout.reconfigure(encoding="utf-8")`.

4. **Большая работа в кириллическом каталоге** — сделать переход (junction)
   на ASCII-путь и работать через него, файлы остаются те же:

   ```powershell
   cmd /c mklink /J "C:\work-src" "C:\Проекты\Выгрузка конфигурации"
   ```

5. **`.bat`/`.cmd` для запуска 1С** — кодировка cp1251 (не UTF-8!). Готовить
   такие файлы конвертацией из UTF-8-исходника, не писать напрямую.

6. **Кириллица в учётных данных 1С — граница Win32.** Запуск 1cv8 с русским
   именем пользователя из PowerShell/Python теряет кириллицу на уровне
   Windows API; это не лечится сменой кодовой страницы или BOM. **Надёжное
   решение одно — завести в базе ASCII-пользователя** для агента и автоматизации
   (`agent`, `runner`): все скрипты остаются чисто ASCII, любая среда работает.
   Для CI это единственный устойчивый вариант.

## Маркеры для распознавания на лету

- «Пользователь ИБ не идентифицирован» → кириллица в имени пользователя,
  см. правило 6.
- `РђРґРјРёРЅ...` — UTF-8 байты, прочитанные как cp1251.
- `Р‘Р°Р·РѕРІС‹Рµ` в выводе PowerShell → чтение UTF-8 файла без `-Encoding UTF8`.

## Дисциплина

1. Не предлагать «пересоздать без кириллицы», если человек дал кириллический
   путь — это его выбор; переход на ASCII-путь (правило 4) менее инвазивен.
2. Не выпиливать кириллицу из содержимого файлов «для простоты» — русский
   текст в 1С-проектах это норма, а не проблема.
3. Bash сломался на кириллице — сразу PowerShell, не пробовать Bash третий раз.
