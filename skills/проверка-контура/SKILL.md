# Проверка контура: диагностика без правок

Агент осматривает свой контур и выдаёт таблицу состояния. Режим — **только
чтение**: команды вида `--version` и `--selftest`, чтение файлов набора.
Ничего не устанавливать, не править, не удалять, не «подчинять по ходу» —
починка любой найденной проблемы предлагается отдельно и ждёт «да».

## Статусы

- **OK** — проверено, работает.
- **WARN** — работает, но с оговоркой (старая версия, неотмеченный профиль).
- **FAIL** — сломано; в этой же строке — одно выполнимое действие.
- **SKIP** — часть контура сознательно не ставилась; это не ошибка.

Правила отчёта: каждая строка = проверка + статус + для WARN/FAIL одно
конкретное действие (команда или страница набора, не «проверьте настройки»).
**Секреты не печатать**: значения токенов, ключей и паролей в отчёт не попадают
ни при каком статусе — только «найден/не найден»; файлы с секретами не читать.

## Блок А — правила подключены

| Проверка | Как | FAIL → действие |
|---|---|---|
| Точка входа | `CLAUDE.md`/`AGENTS.md` в корне рабочего каталога | открыть агентскую среду в каталоге набора |
| Ядро правил | перечисли 4 файла `rules/` **из памяти сессии**, потом сверь с диском | перечитать по порядку из точки входа |
| Профиль модели | в точке входа отмечен ровно один пункт | отметить профиль (не знаешь — «слабая») |
| Синхронность точек входа | `CLAUDE.md` и `AGENTS.md` не расходятся по содержанию | доложить разницу человеку |

Если 4 файла ядра из памяти не перечисляются — это и есть ответ «правила
не загрузились»: статус FAIL, дальше блоки идут своим чередом.

## Блок Б — базовые инструменты

`git --version`, `py -3 --version` (или `python3 --version`). Нет python —
FAIL с действием «поставить Python 3 с python.org, галочка Add to PATH».

## Блок В — контрольные точки набора живы

| Проверка | Как | OK когда |
|---|---|---|
| Валидатор | `py -3 tools/validate.py --selftest` | код возврата 0 |
| Точка стенда | `py -3 стенд/проверка-стенда.py --selftest` | код возврата 0 |

Самотест проверяет, что точка умеет быть красной. Провал самотеста опаснее
красной точки: контроль, который не умеет падать, ничего не контролирует.

## Блок Г — полный контур (SKIP, если не ставили)

| Проверка | Как | Примечание |
|---|---|---|
| EDT | исполняемый файл EDT найден (см. install/01) | нет EDT → SKIP всей строки и codepilot |
| codepilot MCP | инструменты MCP отвечают из агентской среды | среда запущена раньше EDT → перезапустить среду |
| Java 21 | `java -version` ≥ 21 | нужна линии проверки кода |
| Линия проверки кода | BSL LS jar на месте, пробный прогон по модулю стенда даёт диагностики | ноль диагностик на стенде = FAIL: линия слепа (см. install/02) |
| Линия тестирования | `oscript -version`, `vrunner version` (без дефисов) | нет → SKIP, поставится по install/03 |

## Итог (обязателен)

1. Таблица всех проверок со статусами.
2. Одна строка вердикта: «контур рабочий» / «контур рабочий, кроме …» /
   «правила не подключены — начните с блока А».
3. Список предложенных починок по FAIL/WARN — **предложить, не выполнять**.
