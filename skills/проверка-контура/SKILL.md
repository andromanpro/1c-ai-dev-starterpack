# Проверка контура

Осмотри файлы, версии и безопасные контрольные точки. Для живых подключений
сначала установи цель и разрешение. Установку и исправления выполняй только
в пределах поручения человека. Сам запрос диагностики разрешает проверку.

## Статусы отчёта

- **OK** — указанная проба дала ожидаемый эффект в указанной области.
- **WARN** — доступно с существенным ограничением, которое названо.
- **FAIL** — обязательная проверка не выполнена или обнаружен дефект.
- **SKIP** — возможность не нужна текущей задаче и пропущена явно.

Каждая строка содержит источник, пробу, результат и ограничение. Для WARN/FAIL
предложи конкретное действие. Значения секретов и файлы учётных данных не читай.

## А. Инструкции и профиль

1. Установи рабочий каталог и фактическую цепочку инструкций клиента.
   Для Codex учитывай AGENTS.override.md и проектные уровни. Для других клиентов
   используй их подтверждённый порядок или явно прочитай канон.
2. Прочитай текущие файлы ядра 01–04, маршруты 05 и выбранный профиль с диска.
   Кратко назови источник профиля, разрешённый объём и запретную цель.
   Воспоминание названий файлов не доказывает загрузку и соблюдение правил.
3. Проверь, что CLAUDE.md направляет к существующему AGENTS.md. Дословное
   совпадение этих файлов не требуется. Для прежней дублированной установки
   предложи сверку противоречий до перехода на ссылочный файл.
4. Профиль применения без выбора — Start. Для способности модели без выбора
   применяется профиль слабой модели. Pro требует соответствующих материалов.
5. Если DSH развёртывает правила, проверь владельца AGENTS и содержание
   пользовательского файла после миграции по `../../docs/клиенты.md`.

Доступность файлов подтверждается чтением. Поведение агента проверяется
сценариями стенда. Не объявляй правила соблюдаемыми только по ответу модели.

## Б. Базовые инструменты и контрольные точки

Команды из корня набора, Python 3.10+. В Windows — `py -3`, в Linux/macOS — `python3`.

| Проверка | Команда | Подтверждение |
|---|---|---|
| Git и Python | `git --version`, `py -3 --version` | Версии получены |
| Валидатор публикации | `py -3 tools/validate.py --selftest` | Грязная и чистая пробы разобраны правильно |
| Стенд | `py -3 стенд/проверка-стенда.py --selftest` | Исходник и обманка красные, встроенный эталон зелёный |
| Упаковка | `py -3 tools/build_editions.py --selftest` | Положительные и отрицательные пробы прошли |

Историю сообщений проверяй через `tools/validate.py --git-log=--all` только
при подготовке публикации этого репозитория. Сохраняй полный вывод и код возврата.

## В. Возможности целевого проекта

Для каждой нужной возможности отдельно проверь конфигурацию без секретов,
видимость операции в текущем клиенте и контрольную пробу на проекте.

| Возможность | Проба | Что нельзя считать успехом |
|---|---|---|
| EDT и метаданные | Прочитать известный объект по полному пути | Исполняемый файл EDT просто найден |
| MCP | Получить доступные операции и вызвать безопасную для проекта | Сервер просто записан в конфигурации |
| Анализ кода | Известное нарушение даёт ожидаемую диагностику | Ноль файлов или слепой анализатор |
| Тестирование | Выполнить известный тест на разрешённой копии | Инструмент сообщил успех при нуле тестов |

Необязательные возможности можно пропустить. Недоступная обязательная проверка
остаётся FAIL с указанием непроверенного уровня.
