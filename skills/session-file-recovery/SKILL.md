# Восстановление файла из журналов сессий

Claude Code хранит каждую сессию как JSONL-журнал. Любой `Write`/`Edit`
записан с полным содержимым. Значит затёртый файл детерминированно
восстанавливается повтором операций — даже без git и резервных копий.

## Когда применять

- Файл перезаписан «слепым» Write (создали поверх существующего).
- Файл удалён, корзина не помогла.
- Каталог **не** под git — типовой случай рабочих папок с документами.

**Не применять:** каталог под git (`git restore` / `git reflog` быстрее
и надёжнее); правка в текущей сессии (среда сама следит за состоянием).

## Механика (почему именно так)

1. Файл часто **создан в одной сессии, отредактирован в других** — операции
   ищутся по **всем** журналам проекта, не по одному.
2. Порядок применения — глобальный по времени записи, не по порядку файлов.
3. База — последний `Write`; далее каждый `Edit` как замена строки.
4. Контроль целостности: если старая строка Edit не находится в текущем
   состоянии — цепочка порвана (файл правили вне агента: другой редактор,
   Конфигуратор, руками). Скрипт считает такие разрывы и отказывается
   перезаписывать цель, пока они есть.

## Где журналы

```
<домашний каталог>/.claude/projects/<слаг-проекта>/<ид-сессии>.jsonl
```

Слаг = путь рабочего каталога, где `:` и разделители заменены на `-`
(например, `C:\Проекты\Склад` → `C--Проекты-Склад`). Скрипт вычисляет слаг
из текущего каталога сам; другой проект — параметр `--project-dir`.

## Порядок работы

```bash
# 1. Разведка — какие операции есть, ничего не трогая
py -3 skills/session-file-recovery/recover_from_transcript.py --name "файл.md" --list

# 2. Реконструкция в файл.md.recovered — живой файл не трогается
py -3 skills/session-file-recovery/recover_from_transcript.py --path "C:/путь/файл.md"

# 3. Сравнить восстановленное с текущим (размер, содержимое) — глазами

# 4. Только если восстановленное и есть нужный оригинал:
py -3 skills/session-file-recovery/recover_from_transcript.py --path "C:/путь/файл.md" --apply
# (--apply сам делает резервную копию текущего в файл.md.bak-<время>)
```

## Дисциплина

1. **Сначала `--list` и `.recovered`, потом `--apply`.** Слепая перезапись
   живого файла — ровно та ошибка, из-за которой этот навык и нужен.
2. **Разрывов цепочки — ноль** — обязательное условие доверия результату.
   Есть разрывы — результат частичный, честно сказать об этом человеку.
3. **Профилактика лучше**: перед записью в существующий путь — прочитать;
   перед «создай папку X» — посмотреть, нет ли её. И держать рабочие каталоги
   под git — тогда этот навык не понадобится вовсе.
