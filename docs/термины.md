# Термины и язык набора

Норма: русский, «со стороны конфигуратора». Рядовой 1С-ник читает без словаря
стартаперов. Таблица обязательна для всех текстов набора.

## Как пишем

| Вместо | Пишем |
|---|---|
| kit | набор практик / комплект |
| manifest / манифест | принципы / основные положения |
| self-heal | самопочинка / цикл починки инструмента |
| gate / гейт | контрольная точка / шлагбаум / автоматическая проверка |
| skill / скилл | навык агента / инструкция агента |
| hook / хук | проверка перед действием |
| workflow / воркфлоу | порядок работы / рабочий процесс |
| quickstart | быстрый старт |
| setup / сетап | настройка |
| DoD | критерии готовности |
| red flags | тревожные признаки |
| roadmap / роадмап | план развития |
| staging / стейджинг | предварительная площадка |
| runtime / рантайм | среда запуска |
| scope / скоуп | границы / состав |
| hardening | доводка перед публикацией |
| paired-eval | взаимная проверка |
| smoke / смоук | пробный прогон |
| allowlist | список разрешённых исключений |
| skill-pack | набор навыков |
| fix / фикс | исправление |
| review / ревью | проверка / разбор |

## Допущенные исключения

`commit`, `PR`, `MCP`, `CI` — устоявшиеся термины экосистемы, оставляем как есть.
`issue` — только как название сущности GitHub/Gitea, в обычном тексте — «задача».

## Словарь понятий (для новичка)

- **Агентская среда** — программа-оболочка, в которой работает агент: Claude Code,
  Codex CLI, Cursor. Не путать с моделью.
- **Модель** — «мозг» агента: Claude, GPT, DeepSeek. Одна среда может работать
  с разными моделями.
- **Агент** — модель + среда + инструменты + ваши правила.
- **MCP** — протокол, по которому агент получает инструменты (например, доступ к EDT).
- **Навык агента** — файл-инструкция, который агент читает перед типовой операцией.
- **Контрольная точка (шлагбаум)** — автоматическая проверка, которая останавливает
  плохой результат до того, как он навредит: тест, синтаксический контроль, запрет
  в настройках.
- **Форк** — своя копия чужого открытого проекта, в которой можно чинить и дорабатывать,
  предлагая исправления обратно.
