# Повседневный цикл: как выглядит обычный день с агентом

Не теория — рабочие приёмы, снятые с четырёх месяцев реальных сессий.
Предполагается: контур поднят, приёмки стенда пройдены.

## Четыре формы постановки задачи

1. **Стартер + «продолжаем».** Самая частая форма вообще. Контекст лежит
   в файле (`_meta/СТАРТЕР_*.md` по шаблону из `templates/`), сообщение агенту —
   путь и одно слово. Не пересказывайте вчерашнее — ссылайтесь.
2. **Цитата + вердикт.** Копируете кусок ответа агента и через тире дописываете
   решение: «…Поправить? — да, делаем». Решение прикрепляется к месту, где оно
   требуется, без пересказа.
3. **Короткое подтверждение.** «Давай», «делаем», «по порядку». Работает только
   потому, что контекст уже материализован в файлах — иначе агент додумает сам.
4. **Бриф новой задачи.** Номер задачи → система → суть со слов постановщика →
   материалы → ожидаемые артефакты (папка задачи, документ анализа, вопросы,
   поставка). Критерии приёмки — через список артефактов.

## Рабочий цикл одной задачи

**Анализ → согласование → правка → машинная проверка → приёмка.**
На анализе агент пересказывает задачу и предлагает варианты; «давай» относится
к последнему предложенному. Правка — после «да». Проверку агент гоняет сам
и прикладывает вывод. Приёмка — ваша: разница глазами, прогон в тестовой базе.

## Три контура проверки — когда какой

- **Машинный** (синтаксис, тесты, анализатор) — всегда, на каждую правку.
  Бесплатный после настройки, отрабатывает до вашего внимания.
- **Второе мнение** (другая модель или агент) — по порогу: спорная архитектура,
  дорогая ошибка, безопасность, финальная проверка поставки. Приём: не «проверь»,
  а «попробуй докопаться до ошибок» — злой рецензент находит больше.
- **Ваши глаза** — на приёмке результата и везде, где живая база: форму —
  открытием, отчёт — данными.

## Дожим — штатный приём

Первый ответ агента почти никогда не полный. «Посмотри ещё раз, проблем больше»,
«а как ты это проверял?», «покажи разницу, а не пересказ» — это не недоверие
к технологии, это и есть управление ею. Слабой модели — задания по одному
(подтверждено протоколом испытаний: составные задания она теряет молча).

## Конец сессии

Значимая сессия заканчивается стартером: фактовая часть — генератором
(`tools/handoff-facts.py`), рассказ — поверх. Следующая сессия начнётся
с «путь + продолжаем», и ей не придётся верить на слово — факты проверяемы.

Здесь же — взгляд назад: были за сессию столкновения с правилами — агент
дописывает эпизоды в журнал трения. Сами правила при этом не меняются:
процедура и порог — [эволюция-правил.md](эволюция-правил.md).
