# Start и Pro из общего канона

Один main содержит общие правила и два явных профиля. Поставки собираются из
одной ревизии по спискам файлов. Общие файлы сохраняют одинаковые байты.

| | Start | Pro |
|---|---|---|
| Для кого | Первый управляемый цикл с агентом | Разработчик с несколькими инструментами и средами |
| Первый результат | Анализ и согласованная правка на стенде | Паспорт проекта и задача с подтверждённой инструментальной проверкой |
| Материалы | Ядро, стенд, установка, шаблоны, диагностика и справочники | Весь Start, профиль Pro и карта расширенных возможностей |
| Работа | Учебные этапы с согласованием пакетов | Самостоятельное завершение согласованной задачи |
| Качество и база | Общие требования ядра | Те же требования ядра |

Архив Pro добавляет материалы. Выбор поведения выполняет человек в инструкции
проекта. Скачивание архива само по себе не переключает существующий проект.
Способность модели выбирается независимо от профиля пользователя.

Start доступен в [быстром старте](быстрый-старт.md). Описание Pro находится
в полной поставке по пути `docs/pro-возможности.md` и
[в репозитории](https://github.com/andromanpro/1c-ai-dev-starterpack/blob/main/docs/pro-возможности.md).

## Собрать архивы

Команды выполняются из Git-клона, Python 3.10+.
В Windows используется `py -3`, на Linux/macOS — `python3`.

```bash
py -3 tools/validate.py --selftest
py -3 tools/validate.py
py -3 стенд/проверка-стенда.py --selftest
py -3 tools/build_editions.py --selftest
py -3 tools/build_editions.py --output _downloads/editions
```

Результат — `iiskra-Start.zip` и `iiskra-Pro.zip`. В корне каждого архива
есть `EDITION.json` с ревизией, состоянием рабочего дерева и SHA256 файлов.
Одинаковый вход даёт одинаковые байты архива. Сборка из изменённого рабочего
дерева явно отмечается в квитанции. Для выпуска используйте чистый коммит.
Каталог результата должен быть новым. Существующие результаты сохраняются.

Составы заданы в `packaging/common.json`, `Start.json` и `Pro.json`.
Упаковщик берёт только явно перечисленные отслеживаемые обычные файлы.
Проверяются существование, безопасные пути, отсутствие дубликатов, внутренние
ссылки, публичная чистота и идентичность общего состава. Приватный словарь
владельца подключается через `--deny-file`. Перед его публичной отправкой
используйте `--require-deny` по принятому процессу публикации.

```bash
py -3 tools/build_editions.py --output _downloads/editions --require-deny
```

Архивы содержат материалы для использования, сборочные списки и этот упаковщик.
Для повторной сборки требуется Git-клон. CI проверяет оба состава и сохраняет
архивы как артефакты прогона. Автоматическая публикация GitHub Release
в этом изменении не настраивается.

## Совместимость

Прежние пути четырёх файлов ядра, стенда, быстрого старта и шаблона проекта
сохранены. CLAUDE.md читает общий AGENTS.md. При обновлении сначала объедините
проектные условия с новым каноном и проверьте владельца корневого файла,
особенно при развёртывании правил DSH.

Раздельные ветки имеют смысл при поддержке несовместимых поколений интеграций.
Для двух уровней освоения достаточно профилей и составов из общего main.
