# Карточки деформаций: как ИИ ломается и какой шлагбаум это ловит

Каждая карточка — устойчивый способ, которым агент подводит, снятый с реальной
практики: симптомы, чем опасно, и **работающая контрольная точка** набора,
которая это останавливает. Общий закон всех карточек:

> Правило, которое надо помнить, ненадёжно. Надёжен шлагбаум,
> который срабатывает до действия.

---

## 1. Правдоподобие вместо правды

**Симптомы:** уверенные конкретные детали — имена методов, пути, ссылки,
«исторические» связи — которых никто не проверял. Маркеры-стопы: «эволюционировал
из», «исторически связан», ссылка, которую агент не открывал в этой сессии.
**Опасно:** фабрикация самоподтверждается — записанная в файл, она становится
«источником» для следующей сессии.
**Шлагбаум:** правило 04.5 — числа и цитаты только из вывода инструментов этой
сессии, иначе «не проверено»; правило 03.4 — вывод без источника в этом проекте
помечается «гипотеза».

## 2. Ложное «готово»

**Симптомы:** «сделано ✅» без списка проверок; отчёт останавливается там, где
красиво звучит, а не там, где пройден объём.
**Опасно:** непроверенные ✅ копятся в стартерах и планах — следующая сессия
строит на песке.
**Шлагбаум:** правило 02.6 («сделано X, проверено Y, осталось Z»); правило 03.2
(✅ прошлой сессии = непроверенное); контрольные точки, которые агент обязан
прогнать и приложить вывод (стенд — образец).

## 3. Зелёный, который никогда не был красным

**Симптомы:** проверка «всегда проходит»; конвейер зелёный с первого дня;
тесты «работают», но никто не видел их падения.
**Опасно:** зелёный может означать «ничего не проверяется» — неверная метка
исполнителя, не та база, не тот каталог. Годами.
**Шлагбаум:** негативный контроль как обязательный шаг приёмки любой линии —
`install/02` (анализатор обязан ругаться на модуль стенда), `install/03`
(сломанный тест обязан дать красный), самотесты `validate.py`
и `проверка-стенда.py` устроены так же.

## 4. Каскад необратимых действий

**Симптомы:** серия команд, каждая из которых уничтожает путь отката предыдущей;
«сейчас быстро поправлю» на живых данных.
**Опасно:** одна ошибка в цепочке — и восстанавливаться не из чего.
**Шлагбаум:** правила 01.5–01.7 — перед необратимым остановись и покажи;
путь отката обязателен до правки; одна задача — один связный набор правок.

## 5. Правило не становится поведением

**Симптомы:** агент (и человек) знает правило, может его процитировать —
и нарушает в следующем же действии. Записали в память — повторилось.
**Опасно:** знание не срабатывает в момент действия; «мы же договаривались»
не является механизмом.
**Шлагбаум:** сам подход набора — переводить правила в механизмы: проверки
перед действием (`templates/hooks/`), контрольные точки, генераторы вместо
ручных обещаний (`tools/handoff-facts.py`).

## 6. Проверка самым дешёвым инструментом

**Симптомы:** «проверено» = совпадение по текстовому поиску, зелёный вчерашний
прогон, память. Дефект живёт уровнем выше — в исполнении.
**Опасно:** ложная уверенность дешевле правды ровно до первого инцидента.
**Шлагбаум:** правило 04.3 — проверяй на том уровне, где живёт дефект: форму —
открытием, запрос — выполнением, отчёт — данными.

## 7. Молчаливое расширение задачи

**Симптомы:** просили одно — агент «заодно» переименовал, почистил, отрефакторил.
Разница правки не совпадает с заявленным намерением.
**Опасно:** необсуждённые изменения = необсуждённые риски; ревью смотрит не туда.
**Шлагбаум:** правила 02.4 и 04.1 — смежное докладывается, не делается;
чужое красное не чинится без «да»; профиль слабой модели: список изменений
до правки, любой ответ — с «чем проверил».

## 8. Составное задание теряется молча

**Симптомы:** слабая модель выполняет первый пункт из трёх и уверенно
останавливается — без «я не закончила».
**Опасно:** по форме ответ полный, по составу — треть; легко принять.
**Шлагбаум:** профиль слабой модели п. 1 — один шаг за раз; человеку — чек
«что просили / что сделал» в каждом ответе профиля. Подтверждено протоколом
испытаний (v4-flash, 2026-08-20).

## 9. Догадка про окружение

**Симптомы:** ошибка кодировки/пути/доступа — и агент «творчески чинит»:
переписывает файлы, меняет настройки, подбирает варианты.
**Опасно:** лечение симптома ломает больше, чем исходная ошибка; классика —
кириллица в путях Windows.
**Шлагбаум:** профиль слабой модели п. 8 — дословный текст ошибки и стоп;
страница [если-не-получается.md](если-не-получается.md) — диагностика
вместо перебора.

## 10. Контекст чужого проекта

**Симптомы:** в выводах про проект А всплывают имена, числа, детали проекта Б
(или «общеизвестное»). Особенно — при нескольких проектах в одной рабочей области.
**Опасно:** правдоподобная чужая деталь незаметно становится «фактом» проекта
и уезжает в артефакты.
**Шлагбаум:** правило 03.4 — факт обязан иметь источник в этом проекте;
иначе — «гипотеза, требует проверки».

---

Карточки пополняются: поймали новый устойчивый способ подводить — оформляйте
по той же схеме «симптомы → опасно → шлагбаум», и шлагбаум должен существовать,
а не планироваться.
