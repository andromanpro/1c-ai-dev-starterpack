# Линия проверки кода: зачем и как устроена

Теория к сценарию `../install/02-линия-проверки-кода.md`.

## Зачем

Агент пишет код быстро и уверенно — в том числе неправильный. Ваши глаза
не масштабируются, а машинная проверка — да. Линия проверки кода читает
исходники и находит известные классы проблем до того, как код попадёт в базу:
пустые обработчики исключений, подозрительные конструкции, нарушения стандартов.

## Из чего

- **BSL Language Server** — анализатор исходников 1С: сотня с лишним диагностик,
  работает из командной строки, ничего кроме java не требует. Это обязательный
  минимум линии — ставится за десять минут.
- **SonarQube + модуль BSL** — тот же анализ плюс история: веб-интерфейс,
  динамика «стало лучше/хуже», порог качества. Требует docker; ставится, когда
  дозрели до постоянного контроля, — начинать можно без него.
- **АПК** — контроль стандартов 1С по живой базе; нужен на пути
  к «1С:Совместимо», в стартовый контур не входит.

## Главное правило линии

Линия считается установленной только после **негативного контроля**: модуль
стенда с намеренными дефектами обязан дать замечания. Анализатор, который
ни разу не был красным при вас, — неизвестно, работает ли вообще.

## Как этим пользуется агент

По `rules/04-проверка.md` агент запускает анализ сам и чинит красное до доклада.
Команда анализа записывается в инструкцию проекта — тогда «сделано» агента
всегда означает «и проверено анализатором».
